# 01. CMS 사용자 가이드

대상: SUPPORTER / ADMIN / SUPER_ADMIN. 기준: 현재 V10. 계정별 기능 차이는 [권한표](02_ROLES_AND_PERMISSIONS.md)를 따른다. 예시 분류와 검증 콘텐츠가 실제 운영 DB에 있다는 의미는 아니다.

## 로그인과 첫 화면

1. 운영 담당자가 제공한 주소에서 `/login`을 연다. 현재 서버 PC에서는 `http://127.0.0.1:8095/login`이다.
2. 별도로 전달받은 본인 계정으로 로그인한다. 비밀번호 변경이 요구되면 변경 절차를 완료한다.
3. 로그인 후 기존 `/admin`으로 이동할 수 있다. 두 가지 탐색을 쓰려면 `/admin-next?view=manage`를 연다. 주소가 `/admin`인 화면에는 React의 보기 전환이 없다.
4. React 상단의 **기존 관리자 ↗**로 Thymeleaf 화면을 열 수 있다. 로그아웃은 기존 관리자 상단에서 한다. 공용 PC에서는 작업 저장을 확인한 뒤 로그아웃한다.

로그인이 반복되거나 권한 오류가 나면 계정 활성 상태·역할을 운영 책임자에게 확인한다. 다른 사람의 계정으로 우회하지 않는다. 세션 만료 뒤 미저장 입력이 남아 있으면 내용을 별도로 보관하고 다시 로그인한다.

## 두 가지 탐색

| 탐색 | 사용하는 상황 | 실제 동작 |
|---|---|---|
| 사이트 관리 | 전체 글·페이지·파일을 찾거나 전역 설정을 관리 | 기능별 목록에서 선택 |
| 사이트 구조 | 홈페이지에서 고칠 페이지·블록 위치를 찾음 | 현재 등록된 대상과 연결된 목록/편집기로 이동 |

같은 콘텐츠 ID는 같은 ContentEditor, 같은 page ID는 같은 PageEditor를 사용한다. 보기 전환은 저장·발행 작업이 아니다. 같은 편집기의 입력은 유지된다. URL의 `view` 값이 우선하며, 없으면 같은 브라우저 탭에서 계정별 마지막 선택을 기억하고 기본은 사이트 관리다.

SUPPORTER는 사이트 구조와 페이지 편집을 사용할 수 없다. 권한 없는 메뉴는 숨겨지거나 ‘권한 없음’으로 비활성 표시되며 주소를 직접 입력해도 서버가 차단한다. 현재 사이트 구조는 전체 목표 IA가 아니며 사전 없는 후기/FAQ 하위 항목은 ‘사전 연결 전’ 상태다.

## 콘텐츠 작성과 이미지

1. **사이트 관리 → 콘텐츠 관리 → 콘텐츠 목록 → 새 콘텐츠**로 시작한다. 제목을 넣고 **초안 만들기**를 누르면 실제 콘텐츠 ID가 생성되고 공통 편집기로 이동한다.
2. 콘텐츠 유형을 선택하고 제목·본문을 작성한다. FAQ에서는 **질문/답변**, RESTAURANT에서는 **식당명/소개/주소**로 표시된다. 후기·일반·인터뷰는 공통 제목/본문을 사용한다.
3. 기존 카테고리와 신규 유형·기수·주제를 구분한다. 기수/주제는 선택 없음 또는 복수 선택이 가능하다. 현재 원본에는 기수·주제가 0건이므로 아직 선택 항목이 없다.
4. 유형을 바꿨는데 기존 주제가 허용되지 않으면 경고를 확인하고 직접 선택을 정리한다. 시스템이 조용히 삭제하거나 잘못된 주제를 저장하지 않는다.
5. 본문의 원하는 위치에 커서를 두고 편집기의 이미지/첨부 도구를 사용한다. 서식·링크·이미지는 공통 rich editor로 편집한다. 미디어 관리에서 이미 올린 파일도 사용할 수 있다.
6. 오른쪽 실시간 미리보기로 내용을 확인하고 **초안 저장**을 누른다. 저장 완료를 확인한 뒤 이동한다.

사이트 구조의 후기/FAQ/맛집 목록에서 생성하면 해당 유형이 초기 선택된 같은 편집기를 연다. 사전이 연결된 주제 화면에서는 주제를 초기 제안하며 작성자가 변경할 수 있다. 별도 전용 저장소가 생기지 않는다.

파일은 건당 5MB 이하이며 JPG/PNG, PDF·UTF-8 TXT·DOCX·XLSX·PPTX·HWP를 지원한다. 이미지는 1,600만 화소 이하로 제한한다. 콘텐츠의 연결 파일은 최대 12개다. 미디어 업로드와 글/페이지 발행은 별개다. 파일만 올려도 공개되는 것은 아니다.

SUPPORTER는 본인이 올린 미디어를 조회·사용·수정한다. ADMIN/SUPER_ADMIN은 전체 미디어를 다룬다. 미디어 영구 삭제는 SUPER_ADMIN만 가능하다. 첨부 연결 해제나 블록 삭제는 원본 파일 삭제가 아니다.

## 자동저장, 초안 저장, 발행

| 작업 | 현재 초안 | 버전 이력 | 공개본 |
|---|---|---|---|
| 입력 후 약 1.8초 자동저장 | 저장 | 생성 안 함 | 유지 |
| 초안 저장 버튼 | 저장 | 명시적 저장 버전 생성 | 유지 |
| 미리보기 | 표시/조회 | 생성 안 함 | 유지 |
| 발행/재발행 | 검증·저장 | 발행 버전 생성 | 새 발행본으로 변경 |
| 이전 버전 복구 | 선택 내용을 새 초안으로 저장 | 복구 전/후 기록 | 유지 |

1.8초는 마지막 변경 이후의 지연 시간이다. 네트워크·검증 오류가 있으면 저장 완료를 보장하지 않는다. 현재 활성화된 편집기만 자동저장하며 숨겨진 화면·브라우저 탭이나 이력 비교 중에는 중지한다. 실패 메시지나 ‘저장 중’ 상태를 확인하지 않고 창을 닫지 않는다. 브라우저 종료 경고는 최후의 보호이며 오프라인 백업 기능이 아니다.

다른 문서로 이동할 때 미저장 확인이 나오면 취소하고 먼저 저장한다. **버리고 이동**은 저장 버튼이 아니다. 저장/업로드 중에는 완료 후 이동한다. 같은 페이지의 블록 선택·보기 전환은 문서를 바꾸지 않는다. 새로고침은 서버에 저장된 내용만 다시 가져오므로 미저장 입력 복구를 보장하지 않는다.

동시 수정 충돌이 나면 자동 덮어쓰지 않는다. 현재 입력을 보관하고 최신 상태를 다시 조회·비교한다. 동일 내용을 수동 저장해도 버전은 남지만 내용이 같으면 revision은 늘지 않을 수 있다. revision과 버전 ID는 다른 값이다.

## 발행·공개 중단·영구 삭제

**발행은 ADMIN/SUPER_ADMIN만 한다.** SUPPORTER가 초안을 저장하면 ADMIN이 기존 목록에서 확인 후 발행한다. 검토 요청·승인/반려 버튼은 없다.

1. React 콘텐츠 편집에서 초안 저장 완료를 확인한다.
2. **발행·상세 관리 → 기존 화면 ↗**를 열어 같은 콘텐츠 ID와 최신 내용을 확인한다.
3. 기존 Thymeleaf 화면에서 미리보기 후 **발행본 저장**을 누른다. 페이지도 React의 **발행 관리 ↗**를 사용한다. 기존 화면의 초안 저장 버튼 명칭은 **임시저장**이다.
4. 발행본과 이력에서 결과를 확인한다. 다른 탭에서 발행했다면 React의 **다시 조회** 또는 발행본 새로고침으로 최신 상태를 확인한다.

게시된 콘텐츠를 수정해 초안 저장하면 ‘미반영 수정’이 될 수 있다. 공개되는 것은 이전 발행본이다. 다시 발행해야 제목·본문·분류·맛집 주소가 공개에 반영된다.

공개에서 내릴 때는 기존 상세 관리 화면의 **공개 중단**을 사용한다. 원본을 계속 편집·재발행할 수 있다. **영구 삭제**는 SUPER_ADMIN이 삭제 영향 화면에서 사용처·사라질 이력을 확인하고 명시적으로 확인해야 한다. 휴지통과 삭제 취소는 없다. 내부에 deleted_at 표식이 남는 콘텐츠도 사용자 관점에서 복구 가능한 삭제가 아니다.

## 페이지·블록 편집

ADMIN/SUPER_ADMIN은 **페이지 관리 → 전체 페이지 현황 → 페이지**로 들어간다. 기존 page ID를 유지하며 편집한다. 새 페이지/slug 변경/영구 삭제는 SUPER_ADMIN이 기존 Thymeleaf 관리에서 수행한다. React PageEditor는 기존 페이지 편집용이다.

1. 실제 순서로 표시된 블록 목록에서 블록을 선택한다.
2. 등록된 입력값과 표시/숨김을 편집한다. 현재 타입은 HERO·TEXT·IMAGE·POSTS·CTA다.
3. **블록 추가**에서 타입을 골라 새 블록을 만든다. 페이지당 최대 30개다.
4. **복제**는 입력값·Variation·표시 상태를 복사하면서 새 block ID를 발급한다. 원본과 복제본은 독립적이다.
5. **위로/아래로**로 순서를 변경한다. 기존 ID와 입력값은 함께 이동한다.
6. **삭제**는 확인창 후 현재 초안에서 제거한다. 삭제 ID는 다른 블록에 재사용하지 않는다. 파일 원본과 현재 발행본은 유지된다.
7. 미리보기 → 초안 저장 → 필요 시 기존 발행 관리에서 발행한다.

Variation은 등록된 표현만 고른다. 현재 HERO는 **기본형(default)/가운데 강조형(centered)**, 나머지는 default다. 자유 CSS나 코드를 넣는 기능은 없다. 숨김 블록은 관리자에서 편집 가능하지만 공개 응답에서는 제외된다.

## POSTS 콘텐츠 연결

| 방식 | 설정 | 결과 |
|---|---|---|
| category | 기존 카테고리 | 해당 발행 글을 최신순 최대 6개. 미지정은 전체 발행 글 |
| query | 유형 1개, 기수·주제 0개 이상, 최신순, 1~20개 | 발행 당시 분류로 조회. 서로 다른 기준 AND, 같은 기준 복수 값 OR |
| manual | 콘텐츠 선택, 위/아래 이동, 선택 해제 | 최대 20개 고유 ID. 선택한 순서 유지 |

방식을 바꿔도 다른 방식의 설정은 보존하고 활성 sourceMode만 사용한다. query/선택 UI의 분류 항목은 실제 사전이 있어야 한다. 같은 이름의 REVIEW/FAQ 주제를 합치지 않는다.

manual은 미발행·삭제·사용 불가 상태도 관리자에서 표시한다. 설정의 ID를 자동 제거하지 않으며 공개에서는 노출 가능한 발행본만 순서대로 나온다. 중복 선택은 차단한다. 원문 콘텐츠를 블록 JSON으로 복사하지 않는다.

페이지 편집기의 미리보기는 **현재 페이지 초안 설정 + 콘텐츠 발행본**이다. 조건 0건은 오류가 아니다. 콘텐츠 재발행과 페이지 재발행은 별개다. 원본 글만 재발행해도 그 글의 최신 공개 내용은 반영되며, 목록 조건·선택 순서를 바꾸려면 페이지를 재발행해야 한다.

## 공용 템플릿

현재 사용·저장·수정·비활성화·복구 모두 SUPER_ADMIN만 가능하다.

- PageEditor **현재 구성을 템플릿으로 저장**: 이름/설명을 입력하고 명시적으로 저장한다. 기존 템플릿 덮어쓰기는 확인한다.
- **템플릿 불러오기**: 활성 템플릿 선택 → 구성/직접 선택 콘텐츠 상태 확인 → 뒤에 추가 또는 현재 초안 교체 → 적용. 교체는 확인창이 있다.
- 적용된 모든 블록은 새 ID를 받는다. 페이지 공개본은 유지된다. 적용 후 페이지 자동저장이 작동할 수 있지만 자동 발행은 하지 않는다.
- **디자인 관리 → 공용 템플릿**: 목록, 이름·설명·활성 여부, 이력을 관리한다. 구성 변경은 페이지에서 편집한 구성을 템플릿으로 저장하는 흐름이다.
- 템플릿 자체에는 자동저장이 없다. 닫기/이동 확인이 나오면 저장 여부를 선택한다.

템플릿 수정·비활성화·복구는 이미 적용된 페이지에 전파되지 않는다. 비활성 템플릿에서만 쓰는 파일도 삭제 보호 대상이다.

## 버전 확인과 복구

1. 편집기에서 초안 저장 완료 후 **버전 이력**을 연다. SUPPORTER는 본인 콘텐츠 조회만 가능하다.
2. 시각·생성자·종류·revision을 보고 버전을 고른다. 콘텐츠는 현재/과거 본문, 페이지/템플릿은 블록 순서·설정을 비교한다.
3. ADMIN/SUPER_ADMIN은 **새 초안으로 복구 → 확인하고 새 초안으로 복구**를 실행한다. 현재 초안을 먼저 보관하며 공개본은 유지한다. 페이지 slug는 복구하지 않는다.
4. 복구된 초안을 미리보기로 확인하고 필요할 때 별도로 발행한다.
5. 템플릿은 SUPER_ADMIN이 **작업본으로 불러오기 → 복구 내용 저장**을 눌러야 반영된다. 활성 여부도 선택 버전의 값으로 돌아가므로 확인한다.

삭제됐던 과거 페이지 블록은 새 ID로 복구될 수 있다. 기존 딥링크가 자동으로 새 ID를 가리키지는 않는다. 없어졌거나 사용할 수 없는 분류/컴포넌트가 포함되면 복구가 거절될 수 있다. 오류를 숨기거나 임의 변환하지 말고 담당 개발자에게 전달한다.

복구가 성공했지만 재조회만 실패했다는 메시지는 **편집 화면 다시 조회**를 사용한다. 같은 복구를 새 작업으로 반복하지 않는다. 발행 버전과 도입 기준점은 모두 보관하며 수동 초안·복구 전/후 이력은 대상별 합산 최근 20개가 기본이다. 자동저장 전부를 되돌릴 수 있는 기능이 아니다.

## 특정 블록 바로 열기

사이트 구조에서 페이지를 펼쳐 블록을 선택한다. 같은 PageEditor가 해당 ID를 선택하고 화면에 보이도록 이동한다. URL 예시는 `/admin-next/pages/65/edit?view=structure&block=실제-block-ID`다. 현재 실제 ID는 [운영 데이터 가이드](10_OPERATING_DATA_AND_IA.md)에 있다.

URL을 복사하거나 새로고침·뒤로/앞으로 이동해도 저장된 대상 ID를 사용한다. 숨김 블록은 숨김 표시와 함께 접근할 수 있다. 삭제/없는/잘못된 ID면 ‘연결된 블록을 찾을 수 없음’을 확인하고 페이지 수준에서 대상을 다시 선택한다. 내용·순서가 비슷한 블록으로 자동 대체하지 않는다.
