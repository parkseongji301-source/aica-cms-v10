# 03. CMS 운영 가이드

대상: 운영 담당 ADMIN/SUPER_ADMIN. 버튼 사용법은 [사용자 가이드](01_USER_GUIDE.md), 허용 범위는 [권한표](02_ROLES_AND_PERMISSIONS.md)를 따른다. 이 문서는 반복 작업의 순서와 완료 기준이다.

## 작업별 절차와 공개 반영 시점

| 작업 | 수행 순서 | 완료 확인 / 공개 경계 |
|---|---|---|
| 신규 콘텐츠 | 목록 → 새 콘텐츠 → 초안 생성 → 내용/유형/미디어 → 초안 저장 | ID·저장 완료·수동 버전 확인. 발행 전 공개 조회 불가 |
| ADMIN 발행 | 저장된 초안 검토 → 발행·상세 관리 → 최신 내용/미리보기 → 발행 | 새 publication/PUBLISH 이력 확인. 이때 공개 API 변경 |
| 게시 글 수정 | 같은 ID 편집 → 자동/명시 저장 → 검토 → 재발행 | 저장 중 이전 공개본 유지. 유형·기수·주제·주소도 같은 원칙 |
| 공개 중단 | 기존 상세 관리 → 대상/최신 revision 확인 → 공개 중단 | 공개 API에서 제외. 편집 원본은 유지, 재발행 가능 |
| 영구 삭제 | SUPER_ADMIN → 삭제 영향 확인 → 사용처·이력 손실 확인 → 명시적 삭제 | 휴지통 없음. 일반 운영의 내리기는 공개 중단을 우선 |
| 미디어 사용 | 업로드 → 원하는 본문/블록/첨부 위치에 연결 → 문서 저장 | 업로드만으로 공개되지 않음. 연결 문서 발행 후 공개 조건 충족 |
| 미디어 삭제 | SUPER_ADMIN → 사용처 조회 → 모든 참조 확인 → 삭제 | 초안·발행본·템플릿·보관 버전 중 한 곳이라도 참조하면 차단 |
| 페이지 수정 | 전체 페이지 또는 구조에서 같은 page ID → 문구/블록 편집 → 초안 저장 → 미리보기 → 발행 관리 | 저장/복구/템플릿 적용만으로 공개본 변경 안 됨 |
| 블록 변경 | block ID 선택 → 입력/표시/Variation/복제/이동/삭제 → 저장 | 이동/내용 수정은 ID 유지, 복제/신규는 새 ID |
| POSTS 연결 | 소스 방식 선택 → 필터/선택 순서 → 발행 콘텐츠 미리보기 → 페이지 저장/발행 | 페이지 조건 발행과 글 원본 발행을 각각 확인 |
| 템플릿 저장 | SUPER_ADMIN → 현재 구성 저장 → 이름/설명 → 명시 저장 | 템플릿에만 반영. 이미 적용한 페이지 불변 |
| 템플릿 적용 | 활성 템플릿 → 구성·참조 상태 → 추가/교체(확인) | 새 ID의 초안 블록. 재발행 전 공개본 유지 |
| 버전 복구 | 이력 선택 → 현재와 비교 → 새 초안 복구 → 미리보기 → 필요 시 발행 | 현재 초안을 복구 전 버전으로 보관. 즉시 공개 되돌림 아님 |
| 메뉴·전역 설정 | SUPER_ADMIN → 영향 범위 확인 → 명시적인 저장/순서 저장 실행 | 별도 발행 workflow 없음. 저장된 설정을 다음 조회에서 사용 |

페이지 삭제는 메뉴·홈페이지 첫 화면 연결이 있으면 막힌다. 본문에 직접 입력한 URL이나 외부 사이트 링크까지 자동 정리하지 않는다. 콘텐츠 영구 삭제는 manual 참조 ID를 조용히 지우지 않으며 사용 불가 상태로 남긴다. 관리자가 나중에 선택을 해제한다. 파일은 문서 삭제와 함께 자동 삭제되지 않는다.

## 발행 전 검토

콘텐츠는 제목/본문·맞는 유형·기수/주제·기존 카테고리·이미지/대체텍스트·첨부·주소·링크를 확인한다. 현재 운영 사전이 비어 있으므로 사전 후보를 등록한 것으로 가정하지 않는다. 페이지는 블록 순서·숨김·Variation·버튼 URL·POSTS 결과/개수를 확인한다. 기존 page 65에는 테스트 문구와 관리자 링크가 남아 있어 실제 홈페이지 공개 전에 정리가 필요하다.

홈의 기존 POSTS는 category 미지정이므로 전체 발행 글을 가져온다. FAQ 등을 발행하기 전에 홈 소식의 포함 범위를 운영 책임자가 확정해야 한다. 글 발행만으로 기존 공개 POSTS 결과가 달라질 수 있다.

발행 후에는 관리자 발행본과 익명 공개 API를 구분해 확인한다. 실제 공개 홈페이지가 없으므로 현재는 화면 렌더링 성공을 승인할 수 없다. 공개 API 경계 확인만으로 실제 웹사이트 버튼·반응형·메뉴·미디어 표시가 검수됐다고 기록하지 않는다.

## 자동저장과 작업 교대

작업 완료 시 명시적 초안 저장을 한 번 누르고 저장 성공·버전을 확인한다. 자동저장은 이력을 만들지 않는다. 같은 문서를 여러 탭/운영자가 동시에 편집하는 경우 인수인계할 ID와 마지막 저장 상태를 공유하고 후임자가 다시 조회한다. 충돌 시 임의로 revision을 고치지 않는다.

저장 실패·세션 만료·업로드 중에는 다른 화면으로 이동하지 않는다. 미저장 입력을 안전하게 보관하고 로그인/네트워크/검증 오류를 해결한다. ‘저장 중’에 강제 종료하면 마지막 입력은 잃을 수 있다. 템플릿은 명시적 저장만 한다.

## 미디어가 삭제되지 않을 때

사용처 화면에서 콘텐츠/페이지 초안, 현재 발행본, 활성·비활성 템플릿, 각 문서의 보관 버전을 구분한다. 초안에서 이미지를 지워도 현재 공개본이나 과거 버전에 남아 있으면 계속 보호된다. 파일 삭제를 위해 publication/version FK를 직접 지우거나 버전 보관 정책을 임의로 줄이지 않는다. 합법적으로 보관 기간에서 제거되고 다른 참조가 없어졌을 때 삭제 가능하다.

공개 미디어 URL은 현재 발행 참조가 있어야 읽힌다. 초안·템플릿·버전·로고 설정만으로는 공개되지 않는다. 같은 파일이 다른 공개 글에 있으면 한 글을 내린 뒤에도 계속 접근될 수 있다.

## 설정별 영향 범위

| 대상 | 저장/발행 방식 | 주의 |
|---|---|---|
| 콘텐츠/페이지 | 초안 저장과 발행 분리 | 공개본은 publication |
| 템플릿 | 명시 저장 즉시 이후 불러오기에 반영 | 기존 페이지 전파 없음 |
| 메뉴 순서·노출·연결, SNS/외부 링크, 공통 스타일·기본 정보 | 명시 저장 | 전역 영향. 자동저장·별도 설정 publication 없음 |
| PAGE 메뉴의 공개 이름·slug | 연결 페이지의 발행본에서 조회 | 초안 제목 변경과 공개 이름 변경은 다를 수 있음 |
| 미디어 이름·alt | 공용 메타데이터 저장 즉시 | 과거 파일명/alt를 version 복구로 전역 되돌리지 않음 |

공개 API에 사이트 기본 정보·SNS·공통 스타일 전체 응답 계약은 없다. 설정을 저장할 수 있다는 사실과 실제 홈페이지가 그것을 렌더링한다는 것은 다르다. 메뉴 공개 API는 있지만 외부 홈페이지 라우터가 필요하다.

## 장애 연락 시 남길 정보

시각(표시 시간대 포함), 화면 URL, 역할, 문서 ID/block ID, 수행 작업, 오류 문구, 마지막 저장/발행 시각을 남긴다. 비밀번호·세션·CSRF 값이나 불필요한 개인정보를 보내지 않는다. 담당 개발자는 로그와 revision/version/activity를 연결해 확인한다.

문서 수준 실수는 버전에서 새 초안 복구를 먼저 검토한다. 서버/DB 장애는 [백업·복구 절차](08_BACKUP_AND_RECOVERY.md)로 구분한다. 영구 삭제 취소나 DB 손상 복구를 버전 UI가 제공한다고 가정하지 않는다.
