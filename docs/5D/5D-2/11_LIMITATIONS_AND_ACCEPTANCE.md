# 11. 알려진 제한사항·후속 검증

이 문서는 테스트 성공으로 지워서는 안 되는 현재 범위를 정리한다. 5D-2는 문서 작성 단계이며 5D-3 최종 검수나 실제 홈페이지 렌더링 E2E를 완료한 단계가 아니다.

## 실제 홈페이지와 전체 IA의 납품 범위 결정

최종 인수 전에 고객·납품 업체가 아래 중 어느 범위를 계약/검수 기준으로 삼을지 기록해야 한다. **현재 구현 근거로는 A 범위까지 설명할 수 있으며 B를 완료했다고 표현할 수 없다.** 어느 쪽을 택할지는 문서 작성자가 대신 확정하지 않는다.

| 선택 | 의미 | 남는 작업 |
|---|---|---|
| A | 현재 V10 납품은 콘텐츠·페이지·블록 CMS, 공용 템플릿, 이력/복구, 공개 API까지 | 실제 홈페이지 제작 시 최종 IA/라우트/메뉴/블록 연결과 renderer E2E 수행 |
| B | 현재 납품에 목표 전체 계층 IA 관리까지 포함 | 계층 구조·연결 관리·권한·공개 라우팅 계약을 별도 기능 범위로 설계·개발·검수해야 함 |

모든 IA가 비어 있다는 문제가 아니다. 현재 V10의 평면 메뉴에는 parent_id가 없고 관리자 트리는 고정 콘텐츠 경로와 실제 페이지/블록 조합이다. 따라서 전체 목표 IA의 깊이를 만들려면 단순 데이터 입력만으로 해결되지 않는 부분이 있다. 기존 DB에 임의 topic이나 가짜 page를 넣어 이 차이를 가리지 않는다.

| H2 업그레이드·workaround 제거 | 미실행 | 별도 release에서 종료/재연결/rollback·전체 회귀 후 결정 |

| version/미디어 용량 | 발행·baseline 무기한 보관, 초안/복구 최근 20 | 용량·백업 크기 모니터링 정책 결정 |

원본은 이미 V10이다. ‘원본 V3와 검증 V10의 차이’는 전환 전 과거 위험이며 현재 상태처럼 쓰지 않는다. 대신 V3 rollback은 전환 이후 운영 변경을 포함하지 않는다는 손실 범위를 유지한다.

## 기능 경계

- React에서 편집·초안 저장·비교/복구를 하고 발행·공개 중단·영구 삭제는 기존 Thymeleaf 동선을 재사용한다. 기존 관리자는 삭제되지 않았다.
- 공용 템플릿 사용/관리/복구는 SUPER_ADMIN만 가능하다. ADMIN 사용 권한을 임의로 확대하지 않는다.
- 공통 컴포넌트 화면은 등록된 정의 확인용이다. 임의 코드/CSS 등록, 컴포넌트 제작, 일반적인 활성/비활성 관리 빌더가 아니다.
- 새 페이지/slug는 SUPER_ADMIN의 기존 화면에서 관리한다. 템플릿을 이용한 자유 URL 생성·전체 IA 자동 등록은 없다.
- 운영 사전 CRUD UI/API는 없다. `/classifications`는 조회용이다.
- 승인/반려, 휴지통, 개인 템플릿은 없다. 영구 삭제된 대상의 version도 함께 제거되므로 휴지통 대용으로 쓸 수 없다.
- 과거 version은 snapshot 내용과 설정을 비교/복구한다. 당시 POSTS가 보여줬던 모든 콘텐츠 결과나 과거 홈페이지 전체를 재현하지 않는다.
- 과거 version의 분류·컴포넌트가 현재 유효하지 않으면 복구가 거절될 수 있다. 값을 조용히 지우거나 추측 변환하지 않는다.
- 공개 기본정보/SNS/스타일 전체 API 계약은 없고 로고 설정만으로 파일이 공개되지는 않는다. 메뉴/미디어 메타데이터는 별도 발행 snapshot이 없다.
- 방문 통계는 실제 홈페이지 미연결 상태다. 기존 예시 통계를 실제 방문 데이터로 납품하지 않는다.

## 실제 홈페이지 확보 후 필수 E2E

1. 홈페이지 소스·실행 주소·API origin/proxy·방문자 라우터·최종 IA를 확인한다.
2. page 65 또는 승인한 최소 페이지를 공개 renderer에 연결한다. 먼저 테스트 문구/관리자 URL을 정리할 운영 승인을 받는다.
3. 관리자 초안 수정 → 공개 화면 불변 → 관리자 미리보기 → 발행 → 공개 화면 변경을 확인한다.
4. 실제 HERO/TEXT/IMAGE/POSTS/CTA, default/centered, hidden, block ID·링크·모바일 표시를 검수한다.
5. category/query/manual, 발행 분류·맛집 주소, 미발행/삭제 제외, manual 순서, 템플릿 생성 블록을 대조한다.
6. 공개 미디어 URL/다운로드, CORS·메뉴 라우팅, 공개 중단 이후 접근 제한을 실제 주소에서 확인한다.

현재 성공한 것은 API 계약과 발행 경계이며 위 웹사이트 렌더링 E2E는 수행되지 않았다.

## 5D-3 인수 검수에서 남길 기록

범위 A/B 결정, 실제 사용자별 역할 시나리오, 원본 데이터/사전 승인 여부, 비밀값 없는 실행/복구 인계, 새 운영업체의 독립적인 문서 따라 하기, backup restore 담당자/소요 시간, 잔여 위험 수용자를 기록한다. 실제 원본에 시험 글을 남기는 검수는 피하고 쓰기 회귀는 승인된 사본에서 수행한다. 현재 서버를 멈추는 재시작/복구 리허설도 별도 검수 일정으로 진행한다.

과거 검증은 [5C-2 성공 기록](../../PHASE5C2_RETRY_RESULTS.md), [버전 기능 결과](../../PHASE5B2B2_VERSION_HISTORY.md), [5D-1](../5D-1/OPERATING_DATA_PLAN.md)에 구분돼 있다. 각 문서의 당시 사본 ID/포트/테스트 수를 현재 실제 운영 데이터나 이번 5D-2 신규 시험 결과로 복사하지 않는다.
