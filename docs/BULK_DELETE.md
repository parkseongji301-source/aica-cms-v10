# 목록 선택과 삭제

2026-09-30 요청에 따라 콘텐츠, 휴지통, 미디어, 메뉴, SNS/외부 링크 목록에 체크박스와 선택 삭제를 추가했다. 전체 페이지 현황은 후속 UX 요청에 따라 체크박스와 선택 삭제를 제거하고 개별 삭제만 유지한다.

미디어의 전체 선택은 검색·새로고침 버튼 옆에서 제거했다. 파일 목록 위의 기존 안내 줄 왼쪽에 이름이 있는 체크박스를 두고, 선택 삭제는 오른쪽에 배치해 선택과 삭제 조작을 구분한다.

- 전체 선택은 **현재 표시된 목록**에만 적용된다. 검색·필터·페이지·화면이 바뀌면 선택을 해제한다.
- 별도의 선택 바나 선택 해제 버튼은 두지 않는다. 기존 표 머리글의 체크박스를 다시 눌러 전체 선택을 해제하고, 선택 삭제는 기존 목록 상단의 개수·검색·제목 줄에 배치한다. 표가 카드로 바뀌는 모바일 콘텐츠 목록과 미디어·메뉴·링크는 기존 상단 줄에 체크박스만 둔다.
- 목록의 개별 삭제와 선택 삭제는 동일한 확인 창을 사용한다. 대상 이름과 수량을 확인한 뒤 실행한다.
- 콘텐츠는 기존 휴지통 API로 이동한다. 휴지통·페이지·미디어·메뉴·링크는 복구 불가 확인란이 필요하다.
- 삭제 권한을 유지한다. 페이지의 메뉴 연결과 미디어 사용 위치를 확인하고, 서버에서도 기존 사용 제한과 권한을 검사한다.
- 콘텐츠 revision은 확인 창을 열기 전에 조회한다. 휴지통과 페이지는 조회된 목록 revision을 사용한다. 확인 이후 수정된 항목은 서버의 기존 충돌 검사로 보호된다.
- 요청은 순서대로 한 번씩 보낸다. 개별 실패는 항목과 이유를 남기며, 연결·인증·권한 오류 시 남은 쓰기를 중단한다. 자동 재시도하지 않는다.
- 작업 중 중복 제출, 확인 창 닫기, 다른 화면 이동을 막는다. 메뉴 순서·입력 또는 파일 정보의 미저장 변경이 있으면 선택 삭제를 비활성화한다.

기존 API와 승인 JAR, DB 구조는 변경하지 않았다. 페이지 삭제는 기존 폼 API를 호출하며, 실패 시 편집 화면으로 돌아오는 응답을 성공으로 간주하지 않는다. 메뉴·홈페이지 연결이 있는 페이지는 기존 서버 규칙으로 삭제할 수 없다.

## 검증

프런트엔드 테스트 54건과 TypeScript/Vite 빌드를 통과했다. `frontend/tests/bulk-delete.html`은 모든 요청을 예시 데이터로 대체하는 개발용 검증 화면이다. 실제 서버로 요청하지 않으며 배포 빌드에 포함되지 않는다. 부분 성공·수정 충돌, 필터 변경 시 선택 해제, 권한 없는 사용자, 사용 중인 미디어 제외, 페이지 연결 보호, 영구삭제 확인란, 메뉴·링크 선택, 모바일 체크박스 배치를 검증했다. 실제 업무 데이터 삭제는 수행하지 않았다.

## 이 PC 실행

저장소 루트의 `START.cmd`와 `STOP.cmd`는 `.cache/current-ui.json`에 기록된 현재 실행본과 검증된 UI release를 사용한다. 이동 ZIP의 원래 START.cmd는 원본 UI를 시작하므로, 새 UI 작업 이후에는 저장소 루트의 시작·종료 파일을 사용한다. 원본 이동 묶음과 이전 UI는 보존한다.
