# 콘텐츠 목록 UX — 재설계 1·2번

2026-09-29, `AICA_V11_IA_UX_UI_재설계안.md`에 따라 목록 배치와 분류 필터 표시를 함께 개선했다. 이후 3번 글쓰기 변경은 진행하지 않았다.

## 적용 범위

- 콘텐츠 작업 목록을 제목·작성 버튼 → 게시 상태 → 검색 → 접이식 분류 필터 → 적용 조건 → 결과 목록 → 페이지 이동 순으로 배치한다.
- 상태 표시 이름은 전체 / 임시보관 / 게시됨 / 비공개다. 기존 DRAFT / PUBLISHED / PRIVATE와 pending 값은 유지한다.
- 목록은 제목·상태·유형·기수/주제·작성자·최근 수정·편집을 표시한다. 기존 카테고리는 제목 아래 보조정보로 유지한다.
- 모바일에서는 상태·제목·최근 수정·편집을 우선 표시하고 분류·작성자·카테고리는 펼쳐 확인한다.
- 유형·기수·주제·기존 카테고리는 펼쳐 선택한다. 유형·기수·주제 복수 선택과 기존 유형별 주제 합집합/해제 규칙을 유지한다.
- 검색·상태·분류 조건을 칩으로 표시하고 개별 해제 및 전체 초기화를 제공한다. 분류 초기화는 기존처럼 유형·기수·주제만 해제한다.
- 후기/FAQ/맛집의 기존 탐색 범위는 고정 표시하며 초기화해도 유지한다. 주소의 알 수 없는 분류도 적용 조건에서 해제 가능하다.
- 검색 결과 없음·등록된 콘텐츠 없음·조회 오류를 구분한다. 서버가 반환한 전체 결과 수만 표시하며 새 상태별 집계·정렬·필터 API는 추가하지 않는다.

## 기능 동결

DB, API, 권한, 생성·저장·게시·버전·휴지통·복원과 기존 편집 경로를 변경하지 않았다. 기존 필터 함수와 URL 처리, 검색 조건의 AND/OR, 작성창 초기값을 재사용한다. 대시보드의 기존 표는 변경하지 않고 목록 전용 컴포넌트와 CSS로 범위를 제한했다.

## 검증

- 기존 프런트엔드 테스트 48건, TypeScript 검사와 Vite 빌드 통과.
- 분리된 메모리 샘플 환경에서 검색, 유형 복수 선택, 개별 해제, 전체 초기화, 상태 전환, 빈 결과, 알 수 없는 기수/주제 오류와 해제, 범위 고정, 편집 후 검색 목록 복귀, 새 콘텐츠 작성창 열기/취소 확인.
- 390px 모바일에서 가로 넘침 없음, 접힌 분류·작성자 정보 열기 확인. 데스크톱과 모바일 화면 증거 보존.
- 샘플 데이터에는 실제 기수·주제 사전이 없어 유효한 기수/주제의 브라우저 복수 선택은 미검증이다. 기존 단위 테스트에서 동명 주제·비활성 주제·복수 유형 합집합·조건 보존을 확인했다. 실제 운영 데이터 작성/게시와 다른 역할 로그인 시험은 하지 않았다.
- 8095 적용 전후 정상 종료 검사에서 전체 36개 테이블 fingerprint, schema, migration 이력이 동일하다. 승인 JAR·receipt·실행 설정 hash도 동일하다.
- 8095 시작 기록의 새 release 경로·manifest와 로그인 응답을 확인했다. `/next-app`은 로그인 보호 대상이므로 비인증 HTTP 요청으로 index 내용은 검증할 수 없었고, 화면 검증은 같은 JAR의 샘플 서버에서 수행했다. 빌드 시 기존 런타임 CSS 경로 및 큰 bundle 경고는 남아 있다.
