# 게시물 휴지통

2026-09-29 사용자 요청에 따라 게시·재게시 다음 기능으로 구현했다. 사이트 관리 / 콘텐츠 작업 구분을 유지하며 글 관리 기능에 한정한다.

이후 V11 RC1을 고정하고 최신 V10 정상 종료 사본으로 공식 승격·rollback까지 검증했다. 최신 상태는 [V11 리허설 결과](V11_REHEARSAL_RESULTS.md)와 [승격 절차](V11_PROMOTION.md)를 따른다. 아래 메모리 프리뷰 기록은 초기 구현 시점의 검증이다.

## 사용 흐름

1. 게시물 편집 화면에서 저장이 끝난 후 **휴지통으로 이동**을 선택하고 확인한다. 기존 상세 관리의 삭제도 휴지통 이동으로 동작한다.
2. `/admin-next/trash`에서 제목·카테고리·이전 상태·작성자·삭제일을 확인한다. 제목/본문 검색과 페이지 이동을 제공한다.
3. **복원**하면 같은 ID의 최신 저장 초안이 **DRAFT(임시보관)**로 돌아온다. 다시 게시해야 공개된다.
4. **영구삭제**는 휴지통에서만 가능하다. 복구 불가 확인란과 최종 버튼을 거친다.

기존 삭제 권한을 그대로 적용해 SUPER_ADMIN만 이동·목록 조회·복원·영구삭제가 가능하다. ADMIN/SUPPORTER의 권한은 확대하지 않았다. 자동 비우기와 일괄 삭제는 제공하지 않는다. 페이지·템플릿·미디어 자체의 삭제 정책은 유지한다.

## 보존과 삭제

- 휴지통 이동: 최신 본문·서식·카테고리·분류·맛집 주소·첨부 연결·기존 발행본·버전 이력을 보관한다. 일반 목록, 편집, 공개 API와 해당 글만 참조하던 공개 첨부 접근에서 제외된다.
- 복원: 최신 초안과 버전 이력을 보존한다. 예전 발행본은 제거하고 DRAFT로 전환한다. 과거 발행 버전 이력은 남는다.
- 영구삭제: 게시물과 소속 데이터·발행본·버전 이력을 삭제한다. 미디어 원본 및 페이지/템플릿에 저장된 직접 선택 ID는 유지한다. 해당 참조는 사용 불가로 표시된다.
- 휴지통에서 사용 중인 첨부·과거 버전 파일은 영구삭제 전까지 보호한다. 공유 파일은 다른 사용처가 남아 있으면 계속 보호한다.
- 모든 변경은 권한·확인 여부·revision·CSRF를 검사한다. 저장과 동일한 잠금/트랜잭션으로 동시 복원·삭제 충돌을 처리한다.

## API

| 동작 | 요청 |
| --- | --- |
| 목록 | `GET /api/admin/next/posts/trash?q=&page=0` |
| 이동 | `POST /api/admin/next/posts/{id}/trash` |
| 복원 | `POST /api/admin/next/posts/{id}/restore` |
| 영구삭제 | `DELETE /api/admin/next/posts/{id}/trash` |

변경 요청 본문은 `{ "revision": 3, "confirmed": true }`이다. 확인하지 않은 요청/버전 누락은 400, 오래된 버전은 409, 대상 상태가 맞지 않거나 이미 처리된 요청은 404다. 목록은 10개 단위이며 검색은 100자 이하다.

## 데이터와 적용 조건

V11은 `post_trash(post_id)`만 추가한다. 기존 `posts.deleted_at`과 함께 복원 가능한 글을 식별한다. 과거 영구삭제된 행을 backfill하지 않으므로 불완전한 옛 데이터를 복원하지 않는다. V1~V10 파일은 변경하지 않는다.

정상 파일 DB 실행은 V11을 검증만 하고 자동 migration하지 않는다. V10 원본과 기존 V10 receipt는 새 서버에서 거부된다. 과거 V3→V10 이관 도구의 목표/manifest는 V10으로 유지했다. 이 도구와 V10 receipt를 V11 적용에 재사용하거나 receipt를 수동 편집하면 안 된다.

현재 변경은 별도 메모리 DB에서 확인한다. 기존 8095 원본·승인 실행 파일·receipt·UI 배치 폴더는 변경하지 않았다. 운영 반영은 별도 사본에서 V10→V11 이관을 검증하고 해당 버전의 적용 절차를 준비한 다음 진행해야 한다. 현재 UI를 V10 서버에 단독 배치하지 않는다.

## 검증

- 실제 HTTP 요청으로 휴지통 이동·복원·재게시·영구삭제, 권한/CSRF/세션/확인/버전 충돌, 검색·페이지 이동, 동시 복원/영구삭제를 확인한다.
- 원본 미디어·본문·분류·맛집 주소·버전 이력 보존, 참조 보호와 영구삭제 후 해제를 확인한다.
- 과거 영구삭제 행 제외, V10→V11 기존 모든 컬럼 보존, 반복 migration 무변경, V10 DB·receipt 차단을 확인한다.
- 파일 DB에서 서버 종료/재시작 후 휴지통 목록과 복원을 확인한다.
- React 빌드·기존 프런트엔드 검사 및 브라우저에서 이동→목록→복원→같은 글 편집 흐름을 검증한다.

2026-09-29 검증 결과: 백엔드 165건과 프런트엔드 48건 통과. 별도 기존 DB 사본 경로가 필요한 검사 6건은 미설정으로 제외했다. 전체 실행 후 옛 즉시삭제 기대값이 남아 있던 맛집 검사만 보존→영구삭제 기준으로 수정하고 해당 6건을 재실행해 통과했다. 빌드 성공. 별도 임시 파일 DB의 V10→V11 보존 검사와 재시작 검사는 실행해 통과했다.

브라우저에서는 게시→휴지통 이동→복원→같은 글 편집→재게시, 검색/빈 결과, 두 탐색 모드에서의 접근과 영구삭제 확인란을 확인했다. 브라우저의 최종 영구삭제는 실행하지 않았으며 HTTP 통합 검사에서 실제 삭제와 참조 보존을 검증했다.

확인용 서버: `http://127.0.0.1:8097/admin-next/trash?view=manage` (design-preview 메모리 DB, 예시 데이터, 재시작하면 초기화). 검증 로그와 화면은 Git 제외 위치 `.cache/post-trash*`에 보관한다.
