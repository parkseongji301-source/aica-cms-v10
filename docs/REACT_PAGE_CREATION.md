# React 페이지 생성

`전체 페이지 현황` 상단의 `＋ 새 페이지`에서 제목과 선택 입력인 주소를 받아 페이지를 만든다. 성공하면 반환된 페이지 ID의 React 블록 편집기로 이동하며 목록도 갱신한다.

- 기존 `structure` 권한이 있는 최상위 관리자에게만 생성 버튼을 표시한다. 서버의 기존 권한 검사도 그대로 적용한다.
- 기존 `POST /admin/pages/save-json`에 CSRF 헤더와 폼 데이터를 전달한다. 새 서버 API나 DB 변경은 필요하지 않다.
- `id`와 `revision` 없이 `sectionsJson=[]`, `action=save`, `saveIntent=MANUAL_DRAFT`를 보내 빈 임시보관 페이지를 생성한다. 메뉴 연결과 게시는 별도로 진행한다.
- 제목은 필수다. 주소는 소문자 영문·숫자와 단어 사이 하이픈으로 입력하며, 비워두면 서버가 고유 주소를 만든다. 최종 검증과 중복 검사는 서버에서 수행한다.
- 생성 중 중복 제출과 화면 이동을 막는다. 검증 오류에는 입력을 유지한다. 네트워크/서버 응답이 불확실한 경우에는 재생성 대신 목록 확인을 안내한다.
- 생성 성공 후 별도의 상세 조회 성공을 요구하지 않는다. 상세 조회가 실패하더라도 생성 요청을 다시 보내지 않는다.

후기를 넣으려면 생성 후 `블록 추가`에서 글 목록을 추가하고, 기존 `조건으로 불러오기` 설정에서 후기 유형을 고른다. 게시와 메뉴 연결은 기존 관리 기능을 사용한다.

## 검증

- `pnpm --dir frontend test`: 생성 폼의 임시보관 값, 자동 주소, 제목 인코딩을 포함한 단위 테스트.
- `pnpm --dir frontend run build`: TypeScript 검사 및 배포 파일 생성.
- 별도의 `design-preview` 메모리 DB와 승인된 서버 JAR로 생성, 편집기 이동, 중복 주소 안내, 자동 주소 생성을 확인한다. 운영 DB에 테스트 페이지를 만들지 않는다.
