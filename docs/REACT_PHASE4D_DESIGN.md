# 4D 공용 템플릿 설계

2026-09-27. 원본 V3는 그대로 유지하며 최신 4C-2B V8 DB의 새 사본에서만 V9를 검증한다. 기존 수정·미추적 소스, V8 DB와 4C-2B 실행 JAR를 함께 백업한 뒤 진행한다.

## 저장 및 적용

- `page_templates`: ID, 이름, 설명, active, blocks_json, revision, 생성/수정자 users ID 및 시각. V9는 이 테이블만 추가하며 초기 템플릿을 자동 등록하지 않는다.
- blocks_json은 기존 Section 필드를 사용하되 `id`는 제거한다. 페이지 ID·URL·작성자·공개 상태는 포함하지 않는다. schemaVersion/variation/visible과 category/query/manual을 모두 보존한다.
- 저장 시 기존 PageService.previewSections 검증을 재사용한다. 임시 UUID를 부여하여 검증한 후 저장 시 제거한다. 불러올 때도 재검증하고 모든 블록에 새로운 ID를 발급한다. 템플릿 내부 영구 블록 식별자를 만들 필요가 없다.
- POST prepare는 DB를 쓰지 않으며 활성/최신 revision 확인, 현재 manual 콘텐츠 상태 확인, 새 ID가 붙은 블록 목록을 반환한다. 클라이언트가 현재 초안에 추가/교체한다. 기존 PageService 초안 저장·발행·ID 등록/폐기를 그대로 사용한다.
- 페이지와 템플릿 사이 영구 연결은 없다. 템플릿 변경/비활성화는 적용된 페이지에 영향을 주지 않는다.
- 잘못된 컴포넌트/variation/분류/미디어 참조는 적용 시 차단하여 수정하도록 안내한다. manual의 미발행·삭제 ID는 제거하지 않고 상태를 표시한다. 공개 결과는 기존 발행본 조회 규칙을 따른다.

## 권한과 UI

사용자가 이번 단계는 SUPER_ADMIN만 사용한다고 확정했다. 관리와 사용 권한 판정은 별도 함수/응답으로 분리하되 둘 다 SUPER_ADMIN만 허용한다. ADMIN/SUPPORTER는 조회·prepare·관리 API 모두 차단한다. 기존 역할과 페이지 편집 권한은 변경하지 않는다.

디자인 관리 > 공용 템플릿에서 목록/구성/이름·설명·활성 변경을 제공한다. 삭제는 제공하지 않는다. 블록 수정은 기존 PageEditor에서 구성을 편집한 뒤 기존 템플릿의 구성 교체 저장으로 제공하여 새 블록 편집기를 만들지 않는다. 템플릿 revision 충돌은 409로 차단한다.

PageEditor에 불러오기/현재 구성 저장을 추가한다. 불러오기에서 구성 및 콘텐츠 참조 상태를 확인하고 뒤에 추가 또는 초안 교체를 선택한다. 교체에는 별도 확인을 요구한다. 최대 30블록 제한을 유지한다. 적용 중 다른 입력을 덮어쓰지 않도록 현재 문서 변경 여부를 확인한다. 적용 후 기존 자동 초안 저장 정책은 유지하되 자동 발행하지 않는다.

기존 Thymeleaf는 템플릿 기능을 추가하지 않고 복사된 기존 형식의 블록만 취급한다. 기존 ID/variation/POSTS 설정 보존 검증을 수행한다.
