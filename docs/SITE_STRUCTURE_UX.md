# 사이트 구조 화면 단순화 (검수 전, 2026-10-01)

## 1. 결정 (사용자)

- 최상위 항목은 사이트의 고정된 큰 구획이다. 운영자는 평소 최상위를 추가·삭제하지 않는다. 실제 IA가 확정되면 최상위 구조는 **개발 단계에서 운영 데이터로** 세팅한다(제품 코드·migration에 이름을 넣지 않는다).
- 기존 백엔드의 최상위 관리 기능(최상위 생성, 묶음 추가, 삭제, 위치 변경, 구성에서 제거)은 **삭제하지 않고 그대로 두며 UI에서만 숨긴다.** 보조 편집 모드는 만들지 않는다.
- 새 DB/API/migration 없음. 프런트만 바꾼다.

## 2. 화면 (전체 페이지 현황)

| 항목 | 동작 |
|---|---|
| 상단 버튼 | `+ 새 페이지`, `+ 묶음` 제거 |
| 홈(첫 화면) | 완전 고정: 맨 위, 끌기·삭제·위치·구성에서 제거·하위 페이지 없음. 구성 대화상자(메뉴 노출 등)는 그대로 |
| 나머지 최상위 | 강조된 행. `+ 하위 페이지`, 편집, 구조 보기, 구성. 삭제·체크박스·위치·구성에서 제거 숨김. 최상위끼리 끌어서 순서 변경(홈 앞으로는 불가) |
| 하위 페이지 | 끌어서 같은 부모 안 순서 변경, 다른 최상위 행 위에 놓으면 그 항목 맨 끝으로 이동. 삭제·구성·[위치](키보드 대체 수단, 최상위 항목만 선택지) 유지 |
| `+ 하위 페이지` 대화상자 | 부모(그 최상위 항목) 고정 표시. 시작 방법: 빈 페이지 / 콘텐츠 모음 / 저장된 템플릿으로 시작(사용 가능한 템플릿 선택 → 구성 미리보기 → 기존 템플릿 준비 API로 받은 블록 사본으로 생성). 제목·주소 |
| 필터 중 | 끌기 비활성, 안내 |
| 3단계 페이지 | 기존 데이터가 있으면 표시·편집·[위치]는 되지만 끌기와 새로 만들기는 없음(서버 한도 3단계는 그대로) |
| 역할 | ADMIN은 목록·편집만(생성·이동 버튼 없음, 기존 권한과 같음) |

끌기 이동은 기존 `PUT /pages/{id}/placement`(새 부모 맨 끝) 뒤 `PUT /page-order`. 두 번째가 실패해도 새 부모의 맨 끝에 놓일 뿐이다. 규칙은 `pageHierarchy.dropPlan`(순수 함수, 시험 포함)이 정하고 서버가 다시 검사한다.

알려진 한계: 최상위 항목의 순서 변경은 마우스 끌기만 있다(키보드 대체는 하위 페이지 [위치]만, 사용자 범위 결정).
