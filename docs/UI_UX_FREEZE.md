# UI·UX 변경 범위

## 현재 기준: 2026-09-29 실제 운영 V11

사용자 승인으로 React 작성·수정·게시·재게시, 휴지통, V11 migration을 실제 8095에 승격했다. 기존 데이터 보존과 정상 종료·재시작은 PASS했다. 이후 UX 개선의 기능/schema/권한 기준은 [V11 운영 기준점](V11_OPERATING_BASELINE.md)이다. 이번 승격에는 UX/UI 개편이나 다른 신규 기능을 추가하지 않았다.

현재 시작 파일은 `.cache/company-v11/start-ui.ps1`이고 React는 승인 JAR 내부 파일을 사용한다. 아래의 개발 중 미반영 설명과 V10 외부 UI 단독 배치 절차는 과거 기록이며 현재 실행 절차로 사용하지 않는다.

## 2026-09-29 승인된 기능 개발 범위

사용자가 게시물 관리 기능을 먼저 완성한 뒤 UX를 개선하기로 정하고, 첫 작업인 React 작성·수정·임시저장·게시 연결의 개발 시작을 요청했다. 이에 따라 개발본의 게시 API와 해당 경로의 권한 연결, React 게시 버튼, 관련 검증을 변경한다. 아래의 과거 UI 전용 제한과 달리 이번 작업에는 서버 코드 변경이 포함된다. 기존 저장·게시 업무 규칙과 DB schema/migration은 유지한다.

세부 동작과 검증은 [React 게시·재게시 연결](POST_PUBLICATION.md)을 따른다. 운영 8095의 승인 JAR·receipt·DB 및 외부 UI 배치 파일은 이번 개발에서 변경하지 않았다. 개발본은 별도 메모리 DB에서 확인했으며, 새 UI를 운영본에 단독 배치하지 않는다.

## 2026-09-29 게시물 휴지통 개발

사용자가 게시 기능 다음으로 휴지통 구현을 요청했다. 이 범위에는 서버/API, React 화면, V11 추가 테이블과 검증이 포함된다. 글의 삭제를 휴지통 이동으로 바꾸고 복원·영구삭제를 추가한다. 기존 권한 범위는 유지한다. [휴지통 동작·검증·적용 조건](POST_TRASH.md)을 따른다.

기존 8095 원본 DB·승인 JAR·receipt·UI 배치 폴더는 변경하지 않는다. 아래의 UI 단독 배치 절차는 과거 V10 UI 전용 변경에만 적용되며, 게시 API와 휴지통이 포함된 현재 개발본에는 사용할 수 없다.

## 기존 UI 전용 작업 기준

2026-09-28 사용자 지침: 이후 작업은 업무 기능을 동결하고 디자인·동선·UI·UX만 수정한다. 범위를 넘어야 하면 작업 전에 사용자에게 알린다.

- 페이지·콘텐츠 저장, 자동 저장, 발행, 공개 중단, 삭제, 버전 관리와 권한 규칙을 유지한다.
- 서버 API, DB schema, migration, 분류 및 운영 데이터는 UI 작업으로 변경하지 않는다.
- 기존 조회 데이터를 재배치하고 기존 편집 화면으로 이동하는 동선은 변경할 수 있다.
- 메뉴 계층 변경, URL 정책, 새로운 연결 편집 등 업무 기능 추가는 별도 범위다.

## 사이트 구조의 페이지 요약

사이트 구조의 페이지·블록 선택은 기존 `/admin-next/pages` 경로의 `inspect`·`block` 쿼리로 조회 전용 요약을 표시한다. 기존 페이지 목록, 메뉴 연결, 저장된 초안 블록 조회 결과를 사용한다. 초안 구성과 발행 상태를 구분하고 실제 홈페이지 주소를 추정해 링크하지 않는다.

‘페이지 편집으로 이동’ 및 ‘이 블록 편집으로 이동’은 동일한 페이지·블록 ID의 기존 편집기로 사이트 관리 모드에서 이동한다. 미저장 변경 확인과 방문한 편집기 유지 동선을 재사용한다. 기존 편집 URL은 계속 유효하다.

## 현재 PC에 UI만 반영하기

`frontend`의 고정 lockfile로 `pnpm install --frozen-lockfile` 후 `pnpm build`를 실행한다. 산출물은 `src/main/resources/static/next-app`이다.

현재 승인 JAR와 실행 자료는 그대로 유지하고 Spring의 외부 정적 리소스 경로에 UI 산출물을 우선 지정한다. 지정 디렉터리에는 `next-app` 빌드 산출물만 배치하며, 나머지 정적 리소스는 기존 classpath로 제공한다. Java 코드·의존성·DB guard·보안 설정·API는 변경하지 않는다. 이 실행 환경 선택은 로컬 시작 스크립트에 보관하고, 공식 `serve`를 통해 정상 종료·재시작한다.

UI 전용 정적 경로를 제거하고 같은 승인 JAR로 재시작하면 기존 UI로 돌아간다. 승인 JAR·receipt·이관 도구의 파일 내용이나 hash를 편집하지 않는다.

현재 PC의 시작 스크립트는 Git 제외 위치 `.cache/company-v10/start-ui.ps1`, 설정은 같은 디렉터리의 `ui-launch.json`이다. `.cache/company-v10/ui-assets/next-app`에 검증된 빌드 결과를 보관한다. 다음 UI 수정 시 빌드 결과와 이 배치 폴더도 함께 갱신한다. 실행은 기존과 같은 `127.0.0.1:8095`를 사용한다.
