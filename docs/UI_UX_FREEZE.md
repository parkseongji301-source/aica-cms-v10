# UI·UX 변경 범위

## 2026-10-01 작업 항목 조건 가져오기 제거 (사용자 정정)

- 사용자가 원하는 대상은 상위 ‘후기’의 글 목록 조건 설정이 아니라 ‘후기 → 생활’, ‘후기 → 수업’ 각각의 홈페이지 표시 위치·주소 연결이다.
- 직전에 추가한 ‘작업 항목에서 조건 가져오기’ 선택란과 이를 위한 props·스타일을 제거한다. 작업 항목 추가·주제 필터·비노출 페이지 표시 등 이전 기능은 유지한다.
- 저장된 페이지 조건·글·주제는 변경하지 않는다. 실제 홈페이지 주소 연결의 구현은 이번 제거에 포함하지 않는다.

반영·검증: 추가 당시 기록한 네 파일의 UI patch만 역적용했다. 타입 검사·빌드가 통과했고 빌드된 정적 파일 6개가 검증된 RC9의 해당 파일과 모두 동일하다. RC10을 정상 종료하고 현재 DB를 백업한 뒤, 같은 DB를 유지하며 RC9을 다시 선택했다(DB 백업 복원 없음). 공개 응답 9개, DB 40개 테이블의 전체 행 fingerprint·컬럼·migration 이력이 제거 전후 동일하다. 정상 재시작·로그인 응답을 확인했다. 현재 실행은 `.cache/v17-release/V17-RC9-20261001/runtime`이며 `START.cmd`/`STOP.cmd`도 RC9을 따른다. 증거와 최신 DB 백업은 `.cache/v17-release/work-item-import-removal-20261001/`에 보관한다. 제거된 기능의 8101 메모리 미리보기는 정상 종료했다.

## 2026-10-01 글 목록 조건에 작업 항목 가져오기 (제거 전 기록)

- 관리자 페이지 내용 편집의 POSTS ‘조건으로 불러오기’에 ‘작업 항목에서 조건 가져오기’를 추가한다. 기존 콘텐츠 작업 구성의 항목 이름·소속·순서를 사용한다.
- 선택한 항목의 유형 코드와 연결된 주제 ID를 기존 `query.typeCode`·`query.topicIds`에 복사한다. 기존 유형·주제만 교체하고 기수·정렬·표시 개수·블록 제목·주소는 유지한다.
- 조건 복사이며 지속적인 연결이나 자동 동기화가 아니다. 항목 이름 변경·제거는 저장된 블록 조건을 바꾸지 않는다. 직접 조건 선택·자동저장·미리보기·게시 동작을 재사용한다.
- 사용할 수 없는 유형·주제 연결은 선택하지 못하게 표시한다. 작업 항목이 없어도 기존 조건 설정은 가능하다. 서버·API·DB schema V17·migration·공개 홈페이지 편집 기능은 변경하지 않는다.

검증: 프런트 기존 테스트 86개·타입 검사·빌드 통과. 8101 메모리 미리보기에서 후기/FAQ 작업 항목 선택, 유형·주제 교체, 표시 개수 4·최신순·기수 전체 조건 유지, 자동저장, 게시 전 공개 응답 유지, 게시 후 선택 주제의 글만 표시되는 것을 확인했다. 항목 이름 변경·삭제 후에도 저장된 페이지와 공개 응답은 동일하다. 기본 미리보기 사전에는 기수가 없어 기수 유지의 화면 검증은 전체 선택 상태에서 수행했다.

패키징: 다른 작업의 커밋 `a366943`에 서버 변경이 있으므로 현재 RC9 JAR를 기준으로 `static/next-app` 파일만 교체했다. 그 외 모든 JAR 파일은 RC9과 바이트 단위로 동일하다. 해당 커밋의 소스 변경을 되돌리지 않았으며 이번 실행본에 함께 반영하지 않는다. 화면·저장 데이터·공개 응답 증거는 `.cache/work-item-import-preview/`, 검사 로그는 `.cache/work-item-import-*.log`에 보관한다.

8095 반영: `.cache/v17-release/V17-RC10-20261001/runtime`에서 검증용과 동일한 JAR(`7960ba8307a088d3ed88a98540ad7275525a55b051c1e2d0cf831ee5fd913991`)를 실행한다. RC9 정상 종료·DB 백업 후 기존 교체·선택 절차를 사용했다. 공개 응답 9개와 DB 40개 테이블의 행 fingerprint·컬럼·migration 이력이 반영 전후 동일하며 V17 정상 재시작·로그인 응답을 확인했다. 이전 RC9 JAR·receipt는 보존했다. 증거·UI 소스 patch·DB 백업은 `.cache/v17-release/work-item-import-apply-20261001/`에 보관한다. `START.cmd`/`STOP.cmd`는 RC10을 따른다.

## 2026-10-01 비노출 페이지 명칭·행 표시 (사용자 요청)

- 사이트 구조의 `＋ 하위 페이지`를 `＋ 비노출 페이지`로 바꾸고 생성 대화상자와 접힌 개수 표시도 맞춘다.
- 하위 페이지와 작업 항목에 같은 행 간격·들여쓰기·연결선·제목 크기를 사용한다. 비노출 페이지는 보라색, 작업 항목은 파란색으로 구분하고 색상 범례와 구분 이름을 함께 표시한다.
- 페이지의 실제 게시 상태·홈페이지 메뉴 상태·편집·설정·옮기기·삭제는 유지한다. 명칭 변경이며 게시/메뉴 노출 정책이나 DB·API는 바꾸지 않는다. 생성 안내에 게시와 메뉴 설정으로 실제 노출을 정한다는 점을 명시한다.
- 작업 항목과 비노출 페이지 간 전환·호환 동작은 사용자가 제안한 다음 단계로 둔다.

검증: 프런트 테스트 86개·타입 검사·빌드 통과. 8100 메모리 미리보기에서 변경한 버튼·생성 대화상자·페이지 생성·접기/펼치기와 최종 행 배치를 확인했다. 제목 칸의 공간을 확보하고 긴 페이지 주소는 줄임 표시한다. 새 JAR와 RC8의 `static/next-app` 이외 모든 파일은 바이트 단위로 동일하여 서버·설정·의존성·migration 변경이 없다. 이번 표시 변경에서는 서버 테스트를 다시 실행하지 않았다. 화면 증거는 `.cache/hidden-page-preview/structure-preview.png`, 검사 로그는 `.cache/hidden-page-*.log`에 보관한다.

8095 반영: `.cache/v17-release/V17-RC9-20261001/runtime`에 검증용과 동일한 JAR(`c28617e6814015c58247062e8cfff2516196f055669bef897979f6e33032f407`)를 적용했다. RC8 정상 종료·DB 백업 후 기존 교체·선택 절차를 사용했으며 이전 JAR·receipt를 보존했다. 반영 전후 공개 응답 9개, DB 40개 테이블의 전체 행 fingerprint·컬럼·migration 이력이 동일하다. V17 정상 재시작·로그인 응답을 확인했다. 관리자 UI의 인증 요구도 유지된다. 증거와 백업은 `.cache/v17-release/hidden-page-apply-20261001/`에 보관한다. `START.cmd`/`STOP.cmd`는 RC9을 따른다.

## 2026-10-01 주제 필터와 작업 항목 연결 (사용자 요청)

- 유형·기수·기존 카테고리·검색·게시 상태 필터는 유지하고, 주제 선택지만 사이트 구조에 저장한 콘텐츠 작업 항목으로 바꾼다. 이름·소속·순서는 같은 구성 데이터를 사용한다.
- 여러 작업 항목 선택은 각 항목의 글 종류와 주제 연결 쌍을 기준으로 합쳐 조회한다. 동일한 주제를 여러 글 종류가 공유해도 다른 종류의 글이 섞이지 않는다. 기존 역할별 조회 범위·페이지 나누기는 유지한다.
- 기존 `topicIds` 조회와 저장된 글의 분류는 보존한다. 이전 URL의 주제 조건은 적용 조건에서 확인·해제할 수 있다. 삭제·숨김·사용 중지된 작업 항목 조건은 안내하고 임의로 전체 글로 넓히지 않는다.
- DB schema V17과 migration은 변경하지 않는다. 별도 테스트와 미리보기 검증 후 동일 스키마 실행본 교체 절차로 반영한다.

검증: 프런트 86개·타입 검사·빌드 통과. 서버 `-Pegov43-probe verify` 242개 중 236개 통과, 환경 조건 제외 6개, 실패 0. 공유 주제의 글 종류별 정확한 연결, 복수 선택과 중복 없는 집계·페이지 나누기, 유형·기수·검색·상태 조합, SUPPORTER 본인 글 제한, 기존 URL 호환, 항목 삭제·숨김·사용 중지 처리를 확인했다. 8099 메모리 미리보기에서 주제 목록에 작업 항목만 표시되는 것, 복수 선택, 유형 변경, 이름 변경 후 기존 글 조회를 확인했다. 검증 자료는 `.cache/work-topic-preview/`와 `.cache/work-topic-*-verification.log` 등에 보관한다.

8095 반영: 현재 선택은 `.cache/v17-release/V17-RC8-20261001/runtime`이며 검증용과 동일한 JAR(`6aa6849847f656859a357e1692f8190d9159906f1d8d15df79ed34a7c8020bef`)를 사용한다. RC7 정상 종료·DB 백업 후 기존 교체·선택 절차를 거쳤고, RC7 JAR·receipt는 보존했다. 반영 전후 공개 응답 9개와 정상 종료 시 DB 40개 테이블의 행 fingerprint·컬럼·migration 이력이 동일하다. V17 재시작 및 로그인 응답 정상. 소스 patch·추가 소스·DB 백업·검증 증거는 `.cache/v17-release/work-topic-apply-20261001/`에 보관한다. `START.cmd`/`STOP.cmd`는 RC8을 따른다.

## 2026-10-01 콘텐츠 작업 항목 이름만으로 추가 (사용자 요청)

- 사용자가 항목 이름만 입력하면 같은 글 종류의 활성 주제를 재사용하거나 새 주제를 만들고 항목에 연결한다. 주제 생성·유형 연결·항목 저장은 하나의 트랜잭션으로 처리한다.
- 기존 항목의 이름만 수정할 때는 연결된 주제 ID를 유지한다. 기존 명시적 주제 연결 API는 호환성을 유지한다. 같은 유형의 동명 주제가 사용 중지되었거나 여러 개이면 자동 추측하지 않고 안내한다.
- 기존 항목·글·발행본·주제는 일괄 변경하지 않는다. 항목 제거는 기존처럼 메뉴 항목만 제거한다. 권한은 SUPER_ADMIN이며 DB schema V17을 유지한다.
- 화면의 주제 선택을 없애고 이름 입력과 추가/저장으로 단순화한다. 신규 주제를 생성한 뒤 분류 목록과 콘텐츠 작업 탐색을 다시 불러온다.
- 별도 테스트 DB와 미리보기 환경에서 먼저 확인했다. 이후 사용자의 “좋다 이대로하자” 승인에 따라 검증한 동일 JAR를 현재 8095 실행본에 반영했다.

검증: 프런트 테스트 83개·타입 검사·빌드 통과. 서버 `-Pegov43-probe verify` 241개 중 235개 통과, 환경 조건 제외 6개, 실패 0. 이름만으로 기존 주제 재사용/신규 생성, 글 종류별 동명 주제 분리, 사용 중지·모호한 주제 거부, 권한, 이름 변경 시 연결 보존, 항목 삭제 후 글 유지, 저장 실패 시 주제·허용 관계·이력 전체 rollback을 확인했다. 공개 메뉴·구조·페이지 응답과 페이지 revision도 유지된다.

검토용 8098은 `design-preview` 메모리 DB이며 `.cache/name-only-preview/`에 빌드·실행 스크립트·화면 증거를 보관한다. 브라우저에서 후기의 신규 항목 ‘취업 준비’, 주제가 없던 FAQ의 첫 항목 ‘지원 준비’, 기존 항목 이름 변경 뒤 원래 글 조회, 신규 항목에서 주제 자동 선택으로 글 작성 후 목록 조회를 확인했다. 브라우저 오류 없음.

8095 반영: `.cache/v17-release/V17-RC7-20261001/runtime`을 현재 실행본으로 선택했다. JAR SHA-256은 `dc21e09add77be0a453f9e8a7932155eb4737125e1712c34493fbd047cb063e3`으로 검토용 실행본과 동일하다. 기존 RC6을 정상 종료하고 DB를 독점 읽기로 백업한 뒤, 기존 `swap-v12-jar.ps1` 검증·receipt 발급과 `select-v12-runtime.ps1` 선택 절차를 사용했다. 동일 DB 경로를 사용하며 V17 schema와 기존 migration을 유지한다. 이전 RC6 JAR·receipt와 실행 선택 백업은 보존한다.

반영 후 정상 종료·재시작으로 migration 이력·컬럼·40개 테이블의 전체 행 fingerprint가 반영 전과 동일함을 확인했다. 공개 메뉴·구조·게시물·페이지 조회 9개도 응답이 동일하다. 적용 증거·소스 patch·DB 백업은 `.cache/v17-release/name-only-apply-20261001/`에 보관한다. `START.cmd`/`STOP.cmd`는 RC7에 연결된다.

## 현재 기준: 2026-09-30 V12 안정 기준점

기능·schema·권한의 현재 기준은 [V12 안정 기준점](V12_STABLE_BASELINE.md)이다. 이후 Thymeleaf → React 전환도 이 기준과 비교한다. V11 기준점과 rollback 자료는 그대로 보존한다.

2026-09-30 변경은 두 종류다.

- **UI만 변경(동결 범위 안)**: 메뉴 관리의 선택 삭제 제거([목록 선택과 삭제](BULK_DELETE.md)), '디자인 관리'→'공통 구조 관리'·'공용 템플릿'→'페이지 템플릿' 명칭 정리와 공통 스타일 메뉴 숨김([사이드바 정리](SIDEBAR_CLEANUP.md)), 기존 `save-json`을 쓰는 [React 새 페이지 생성](REACT_PAGE_CREATION.md). 서버·API·DB 변경이 없어 V11 JAR에서도 동작한다.
- **동결 예외(2026-09-30 사용자가 V12 기준점으로 채택한 기능 추가)**: [글쓰기 템플릿](WRITING_TEMPLATES.md). 새 `writing_templates` 테이블(V12 migration), 새 관리 API, 후기 편집기의 템플릿 삽입을 추가했다. 기존 저장·게시·휴지통·버전·권한 동작과 기존 테이블 데이터는 바꾸지 않았다.
