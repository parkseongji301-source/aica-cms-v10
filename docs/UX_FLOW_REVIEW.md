# 관리자 업무 동선 점검

점검일: 2026-09-25. 대상: `http://127.0.0.1:8081/admin`.

현재 화면을 직접 탐색하고 템플릿·컨트롤러·저장 처리를 함께 확인했다. 아래 표는 변경 전 점검 기록이다. 이후 사용자의 승인에 따라 권장 메뉴와 동선 개선을 적용했다. 최초 점검은 데이터를 수정하지 않았고, 구현 후 브라우저 쓰기 검증은 별도 메모리 DB에서 수행했다.

## 판단 기준

- 이름 변경 같은 한 작업은 한 화면에서 끝낸다.
- 같은 값을 두 번 입력하거나 같은 의미의 설정을 여러 곳에서 수정하게 하지 않는다.
- 자주 쓰는 기능은 바로 보이고, 드물게 쓰는 선택지는 필요할 때 연다.
- 버튼과 메뉴 이름은 실제로 하는 일을 나타낸다.
- 반복 안내와 홍보 문구는 줄인다. 저장 상태·오류·삭제 영향·통계의 예시 여부는 정확하게 표시한다.
- 운영 대상은 앞으로 연결할 홈페이지다. 별도의 가상 홈페이지를 추가하지 않는다.

## 확인한 문제와 수정 방향

| 우선순위 | 현재 동선·문제 | 수정 방향 |
| --- | --- | --- |
| 먼저 | 글·페이지·카테고리가 각각 콘텐츠 관리·페이지 관리·사이트 구조에 나뉜다. 하위 메뉴는 다른 화면에 가면 다시 접힌다. | 글 관리·페이지 관리·카테고리 관리·파일 관리를 콘텐츠 아래 모으고 자주 쓰는 하위 메뉴를 펼쳐 둔다. |
| 먼저 | 메뉴의 표시 이름을 연결한 카테고리와 별도로 입력한다. 카테고리 이름을 바꿔도 메뉴 이름은 그대로다. | 카테고리 메뉴는 이름을 자동으로 따른다. 페이지 메뉴도 제목을 따르는 것을 기본으로 하고, 외부 링크만 이름과 주소를 입력한다. 기존의 다른 이름 처리와 제목 길이 차이는 구현 시 함께 처리한다. |
| 먼저 | 메뉴 목록에는 이름과 표시/숨김만 보여서 어느 페이지나 카테고리를 여는지 수정 화면에 들어가야 알 수 있다. | 목록에서 `카테고리 · 공지사항`, `페이지 · 소개`처럼 연결 내용을 짧게 보여 준다. 추가할 때 페이지·카테고리 선택 목록을 한곳에서 제공한다. |
| 먼저 | 글 제목을 누르면 상세 화면을 거쳐 수정한다. 별도 수정 링크는 있지만, 페이지 목록의 제목은 곧바로 편집을 열어 동작이 다르다. 글의 삭제·비공개는 상세 화면에만 있다. | 글과 페이지 모두 제목 클릭으로 편집한다. 상태 변경·삭제는 편집 화면의 같은 위치에서 제공한다. 읽기 전용 확인은 필요할 때 선택한다. |
| 먼저 | 글 목록에서 카테고리·검색어를 고른 뒤 편집하고 ‘목록’으로 돌아오면 조건이 사라진다. 특정 카테고리에서 ‘새 콘텐츠’를 눌러도 분류 없음으로 시작한다. | 목록으로 돌아갈 때 검색·분류·페이지를 유지한다. 특정 카테고리에서 쓰기 시작한 글은 그 카테고리를 기본 선택한다. |
| 먼저 | 카테고리 필터 결과가 0건인데 ‘아직 등록된 콘텐츠가 없어요’, ‘첫 번째 소식…’으로 안내한다. 실제로는 다른 카테고리에 글이 있다. | 실제 빈 목록과 필터 결과 없음을 구분한다. `조건에 맞는 글이 없습니다`와 `필터 해제`만 제공한다. |
| 먼저 | 로고는 미디어 관리에서 먼저 업로드해야 한다. 페이지의 독립 이미지 섹션도 기존 파일 선택만 가능하다. 빈 보관함에서는 창을 닫고 다른 업로드 버튼을 찾아야 한다. | 이미지를 사용하는 자리에서 업로드와 기존 파일 선택을 모두 제공한다. 파일 관리는 전체 파일 정리가 필요할 때만 방문한다. |
| 먼저 | 중복 이름이나 사용 중인 항목 삭제 같은 오류를 공통 오류 화면으로 보내는 경로가 있다. 해당 화면에는 게시물 목록·로그인 링크만 있어 원래 작업과 연결되지 않는다. | 입력값과 작업 화면을 유지하고 문제가 있는 항목 근처에 오류를 표시한다. 사용 중이라 삭제할 수 없다면 실제 사용처와 이동 링크를 보여 준다. |
| 다음 | 새 페이지는 처음부터 영문 식별자를 필수로 요구하고, 섹션을 하나씩 추가해야 한다. 식별자가 없으면 자동 저장도 되지 않는다. | 새 식별자는 자동 생성하고 고급 설정에서 수정한다. 기본 본문으로 바로 작성할 수 있게 하며 섹션 구성은 필요할 때 추가한다. 기존 식별자는 자동 변경하지 않는다. |
| 다음 | 글 편집에는 현재 발행 상태와 미반영 수정 여부가 표시되지 않는다. 글 목록에도 미발행 변경 표시가 없지만 페이지 목록에는 있다. 페이지 저장 후 일부 상태 버튼은 최초 화면 상태를 유지한다. | 글·페이지에 같은 상태 표시를 사용한다. 저장 완료·수정 중·확정본과 다른 내용이 있음을 구분하고 저장 응답에 맞춰 버튼도 갱신한다. 홈페이지 전송 여부는 저장 성공과 구분한다. |
| 다음 | ‘공통 컴포넌트’에는 로고·헤더 문구·푸터 문구만 있다. ‘공통 스타일’은 색상 2개와 모서리 선택이다. ‘시스템 설정’의 변경 가능한 값은 목록 개수 하나다. | 디자인은 한 화면으로 모아 색상·로고·상단/하단을 구획한다. 목록 개수는 사이트 기본 설정에 합친다. 독립적인 시스템 설정 메뉴는 없앤다. |
| 다음 | ‘역할 / 권한 관리’에서는 권한을 수정할 수 없고 역할 설명만 읽을 수 있다. 실제 역할 변경은 운영 계정 관리에 있다. 역할 선택에는 ADMIN 같은 코드가 나온다. | 계정 관리에서 역할을 바꾸고 필요한 경우 권한 설명을 펼친다. 독립 안내 메뉴는 제거하고 역할명은 한국어로 표시한다. 비밀번호 초기화·비활성화의 영향 안내는 해당 작업에서 유지한다. |
| 다음 | 카테고리·메뉴·링크 순서를 바꾼 뒤 별도 순서 저장을 해야 한다. 항목 입력 폼과 순서 편집에는 이탈 시 미저장 보호가 없다. | 항목과 순서의 저장 방식을 일관되게 정한다. 순서는 변경 시 저장 상태를 표시하며 자동 반영하거나, 미저장 보호가 있는 명확한 저장 버튼을 사용한다. 이동할 수 없는 첫·마지막 화살표는 비활성화한다. |
| 다음 | 활동 이력에 연속 자동 저장이 여러 줄로 쌓이고 `categories`, `basic`, `siteName` 같은 내부 이름이 보인다. | 기록은 유지하되 기본 목록에서는 자동 저장을 묶거나 필터링한다. 대상 이름과 작업 내용을 운영자가 읽는 표현으로 보여 준다. |
| 정리 | 대시보드의 큰 홍보 배너, 영어 구분 문구, 페이지별 유도 문장, 반복되는 홈페이지 연결 전 안내, 설정 오른쪽 설명 패널이 화면을 차지한다. | AICA 색상·브랜드는 유지하며 운영과 관계없는 배너와 문장을 줄인다. 대시보드에는 통계와 최근 작업을 먼저 배치한다. 연결 상태는 한곳에 간결하게 표시한다. |

## 권장 메뉴

```text
대시보드

콘텐츠
  글 관리
  페이지 관리
  카테고리 관리
  파일 관리

사이트 꾸미기
  메뉴 설정
  디자인 설정

운영 관리
  계정 관리
  활동 이력

설정
  기본 정보
  SNS / 외부 링크
```

글쓰기와 새 페이지는 각 목록의 주요 버튼으로 제공한다. 임시저장·발행 상태는 목록 안에서 필터링한다. 방문자 통계는 대시보드에 유지한다. 미리보기는 편집 화면 옆에 유지한다. 권한 설명은 계정 관리 안에서 열고, 개인 비밀번호 변경은 계정 영역에서 접근한다.

## 안내 문구를 남기는 기준

| 줄일 문구·요소 | 대신 필요한 정보 |
| --- | --- |
| ‘생각을 글로, 소식을 더 풍부하게’, ‘첫 번째 소식을 기다리고 있어요’ | 제목·본문·글쓰기 버튼, 정확한 빈 목록 상태 |
| ‘권한에 따라 전체 콘텐츠를 조회하고 관리할 수 있습니다’ | 실제로 허용되는 메뉴와 버튼 |
| 모든 설정 화면의 같은 ‘페이지 관리로 이동’ 안내 패널 | 현재 설정과 직접 관련된 조작 |
| 상단·편집기·본문 아래에 반복되는 홈페이지 연결 전 설명 | 공통 연결 상태와 실제 저장 결과 |
| 삭제할 때마다 같은 일반 문구 | 삭제 대상 이름과 되돌릴 수 있는지, 사용 중인 위치 |
| 역할 코드와 기술적인 설정 이름 | 관리자·서포터즈 같은 역할명, 실제 변경 항목명 |

자동 저장 상태, 저장 실패, 미저장 이탈 경고, 사용 중인 파일 삭제 제한, 계정 권한 변경의 영향, 통계가 예시 데이터라는 표시는 유지한다. 자동 저장이 확정본을 갱신하는 것으로 오해하게 해서는 안 된다.

## 점검 범위와 근거

- 브라우저에서 대시보드, 글 목록·상세·편집·신규 작성·빈 보관함, 페이지 목록·기존 편집·신규 작성, 카테고리·메뉴 수정, 파일 관리, 디자인 2개 화면, 설정 3개 화면, 계정 목록·생성·역할 변경·권한 안내, 활동 이력, 개인 비밀번호 변경을 확인했다.
- 카테고리 필터 0건과 새 글의 기본 카테고리 초기화를 브라우저에서 확인했다.
- 이름 연결, 오류 처리, 목록 복귀, 순서 저장, 발행 상태 갱신, 자동 저장 기록은 관련 코드도 확인했다.
- 삭제·계정 변경·발행 같은 실제 변경 작업은 이번 점검에서 실행하지 않았다. 오류·삭제 제한의 복귀 문제는 코드 검토 결과다.
- 최상위 관리자 기준의 데스크톱 동선 점검이다. 모바일 전체 동선 및 다른 역할 계정의 실행 점검은 포함하지 않았다.
- 주요 근거: `templates/fragments.html`, `templates/posts/*`, `templates/cms/*`, `templates/accounts/*`, `templates/error.html`, `static/js/cms.js`, `static/js/writing.js`, `cms/SiteService.java`, `cms/CmsController.java`, `post/PostController.java`, `cms/PageController.java`, `common/WebAdvice.java`.

## 적용 순서

1. 메뉴 묶음과 명칭, 카테고리·페이지 이름 연결, 글 목록에서 바로 편집하는 동선을 정리한다.
2. 입력 위치에서 파일 업로드, 검색 조건 유지, 오류 화면 복귀 문제를 해결한다.
3. 상태 표시와 저장 동작을 통일하고 페이지 식별자·권한 안내·디자인 설정을 정리한다.
4. 반복 문구·큰 안내 영역을 줄이고 실제 업무 시나리오로 다시 점검한다.

완료 판단은 ‘공지사항 이름 변경’, ‘검색한 글 수정 후 목록 복귀’, ‘로고 교체’, ‘소개 페이지 작성’, ‘운영자 역할 변경’이 각각 불필요한 화면 왕복 없이 끝나는지로 한다.

## 적용 결과

권장 메뉴 묶음, 연결된 카테고리·페이지 이름 자동 사용, 글 제목에서 직접 편집, 목록 검색 조건 복귀, 선택 카테고리로 글쓰기, 필터 결과 없음 표시를 적용했다. 로고·페이지 이미지·보관함에서 바로 업로드하며, 오류는 작업 화면에 입력값과 함께 표시한다. 사용 중인 항목 삭제가 막히면 접근 가능한 사용처를 연결한다.

새 페이지는 기본 본문을 제공하고 주소를 자동 생성한다. 미완성 이미지·버튼 섹션도 임시저장하며 발행할 때 필수 항목을 검증한다. 글·페이지의 발행 상태와 미반영 수정을 표시하고 저장 후 상태 버튼을 갱신한다. 디자인·기본 설정을 통합하고 계정 목록 안에서 역할을 변경한다. 순서는 저장 버튼과 미저장 이탈 보호를 사용한다. 활동 이력의 임시저장 기록은 기본 숨김 필터로 정리하되 원본 기록은 유지한다.

AICA 색상과 브랜드, 대시보드 방문 통계, 글 서식 도구와 실시간 미리보기는 유지한다. 기존 설정 URL은 호환을 위해 통합 화면으로 연결한다. 공개 홈페이지나 외부 전송 기능은 추가하지 않았다.
