# 글쓰기 템플릿

- 사이트 관리 → 공통 구조 관리 → 글쓰기 템플릿에서 등록·수정·삭제한다. 기존 공통 구조 관리 권한(SUPER_ADMIN)을 사용한다.
- 후기(REVIEW) 편집기의 보관함 옆 템플릿 버튼에서 검색·미리보기·본문 삽입만 제공한다. 다른 콘텐츠 유형에는 노출하지 않는다.
- 기본 동작은 기존 본문 뒤에 추가다. 본문 전체 교체에는 별도 확인이 필요하다. 삽입은 실행 취소 1회로 되돌릴 수 있다.
- 제목·유형·기수·주제는 바꾸지 않는다. 적용된 본문은 사본이므로 템플릿의 이후 수정·삭제에 영향을 받지 않는다.
- 템플릿에는 글과 서식을 저장한다. 사진·첨부는 개별 후기에서 넣는다.
- V12 마이그레이션으로 `writing_templates`와 프로젝트 후기 양식 1개를 추가한다. 삭제한 기본 템플릿을 부팅 시 재생성하지 않는다.

## 저장과 검증

`/api/admin/next/writing-templates`는 목록·상세·prepare를 제공한다. `/manage` 하위 경로만 생성·수정·삭제를 허용한다. 변경은 구조 관리 권한, CSRF, 현재 계정 상태, revision 검증과 트랜잭션 잠금으로 보호한다. prepare는 데이터베이스에 글을 쓰지 않는다. 서버가 검증한 RichTextService 문서와 HTML만 사용한다.

기능 테스트는 생성·수정·삭제, 권한, CSRF, 충돌, 잘못된 문서, HTML 이스케이프, 읽기 전용 prepare를 검증한다. 프런트엔드 테스트는 본문/서식/미디어 보존, 독립 사본, 빈 본문 처리, 크기 제한을 검증한다.

2026-09-30 검증: 프런트엔드 61개 통과. 서버 전체 178개 중 172개 통과, 환경 조건으로 6개 제외, 실패 없음. 빌드 성공. 격리된 메모리 DB에서 관리 화면 등록·수정·재조회, 삭제 확인/취소, 후기 본문 추가·교체 확인·실행 취소·저장/재조회, 다른 유형에서 버튼 숨김을 브라우저로 확인했다. 실제 파일 DB 이전 및 재시작 후 템플릿 1개와 모든 기존 데이터 보존을 확인했다. 실제 서버의 관리 UI는 로그인 상태가 필요하다.

## 현재 PC 실행

정식 기준은 [V12 안정 기준점](V12_STABLE_BASELINE.md)의 V12 RC1이다. 아래는 기능 개발 중 만든 V12 개발 실행본 기록이다.

루트 START.cmd와 STOP.cmd는 `.cache/current-ui.json`의 활성 실행본을 사용한다. V12 개발 실행본은 `.cache/runtime-v12-writing-templates`이며, 고정된 server.jar와 해시로 검증하는 UI 오버레이를 함께 사용한다.

V12PromotionTool은 정상 종료된 V11 데이터베이스의 바이트 단위로 동일한 별도 복사본만 이전한다. 이전 전후 모든 기존 테이블의 열과 행 지문을 비교하고, 기본 템플릿 1개만 추가됐는지 확인한다. 실행 파일 해시와 실제 DB 경로가 일치하는 완료 기록을 발급한다. 기존 트랜스퍼 실행본/DB는 보관된다. 이전 실행본의 승인 기록을 새 실행본용으로 변경하지 않는다.

START는 127.0.0.1:8095에 연결하며 자동 마이그레이션을 하지 않는다. STOP은 JVM 정상 종료 후 DB를 읽기 전용으로 검사한다. `AUTO_COMPACT_FILL_RATE=0`을 유지한다. V12에 작성한 내용이 생긴 뒤 V11로 단순 전환하면 새 내용은 보이지 않으므로, 되돌릴 때는 두 DB를 보관한 상태에서 변경분을 먼저 확인해야 한다.
