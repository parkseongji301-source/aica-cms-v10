# 글쓰기 UX · 재설계 3·4·5번

2026-09-29 `AICA_V11_IA_UX_UI_재설계안.md`를 기준으로 글쓰기 저장·게시 표시, 작성 공간, 서식 도구·미리보기를 함께 정리했다. 6번 콘텐츠 작업 탐색은 이번 범위에 포함하지 않는다.

## 화면 변경

- 상단에 자동저장 상태와 임시보관·미리보기·게시 버튼을 모았다. 임시보관은 기존 수동 버전 저장 동작을 유지한다.
- 게시됨과 미게시 수정 내용을 구분하고, 현재 공개본 보기 경로를 게시 상태 옆에 배치했다. 저장만으로 공개본이 변경되지 않는다는 안내를 추가했다.
- 제목·본문을 주 작성 공간에 두고 유형·분류·기수·주제·맛집 주소 등 기존 입력은 오른쪽 속성 영역에 배치했다. 좁은 화면에서는 한 열로 표시한다.
- 기본 서식과 삽입 도구를 정돈하고 나머지 서식은 추가 서식으로 펼치게 했다. 기존 도구를 제거하지 않았다.
- 작성 내용 미리보기는 필요할 때 열며 PC·모바일 보기를 유지한다. 미리보기 전환 시 본문 편집기를 다시 생성하지 않아 선택·실행 취소 이력을 유지한다.
- 버전 이력·다시 불러오기·휴지통·기존 편집 경로는 더보기에 모았다. 게시본과 작성본의 분류 비교도 유지한다.

## 변경 파일과 동결 범위

`frontend/src/ContentEditor.tsx`, `RichEditor.tsx`, `writing-workspace.css`, `main.tsx`의 화면 구성·스타일·표시 상태만 변경했다. 추가 서식 배치는 콘텐츠 글쓰기에서만 사용한다.

DB schema, API 계약, 권한 조건, 1.8초 자동저장, 수동 버전 저장, 게시·재게시·휴지통 로직은 변경하지 않았다. 본문 저장 형식과 기존 글꼴·크기 값, 첨부 업로드 처리도 유지한다. 서버 코드와 승인 V11 JAR는 수정하지 않았다.

## 검증

- 기존 프런트엔드 테스트 48건, TypeScript 검사, 빌드 및 diff 공백 검사 통과.
- 같은 V11 JAR의 별도 메모리 예시 환경에서 자동저장 → 임시보관 → 최초 게시 → 수정 자동저장 → 공개본 유지 → 재게시 → 공개본 갱신 확인.
- 미리보기 열기·닫기, PC·모바일 전환, 실행 취소·다시 실행, 굵게·글자 크기, 추가 서식, 표 입력창, 버전 이력 접근 확인.
- FAQ 질문·답변 및 맛집 식당명·주소 입력 유지 확인. 390px 화면에서 가로 넘침 없음.
- 8095 UI 적용 전후 정상 종료 검사에서 전체 36개 테이블 fingerprint, schema, migration 이력 동일. 승인 JAR·receipt·원래 실행 설정 해시 동일.
- 운영 DB에서 직접 저장·게시하지 않았다. 실제 역할별 로그인, 첨부 업로드 및 버전 복구·휴지통 실행은 이번 화면 검증에서 수행하지 않았다.
